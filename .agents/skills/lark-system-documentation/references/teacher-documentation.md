# 教师发展服务文档表达

只在当前文档明确归属教师发展服务时使用；其他系统仍按现行治理模板执行。每次先读取实时系统登记，不在本参考缓存编号前缀。

- 仓库存在AGENTS.md及docs/文档编写规范.md时，先读取师资专用规范和对应产品/更新模板。
- 文档负责人按通用规则填写执行时已验证的CLI登录用户，不留空或写待指定；仓库模板中的旧占位不覆盖此规则。
- 师资更新日志沿用[更新日志写法与维护](release-notes-writing.md)，更新[项目登记](project-release-pages.md)中已确认的固定文档：按日期倒序、功能点编号、注意事项放在对应功能下；内部验收过程放维护说明或关联记录。仓库旧模板不覆盖这套用户已确认的写法。
- 产品文档和更新时间线开头先放“文档信息”二列表格，再给简短说明；文档修订、系统/子项目、适用端、状态、维护人和复核日期分别记录。时间线的实际上线日期与产品版本写在各次更新中，补登记日期单独注明，分支/标签等在关联记录中追溯。正文保持业务语言。
- 师资产品文档同样遵循主 Skill 的“产品文档写法”：文档信息标题及信息表置于最前，标题直接说明重点，正文按实际功能或场景组织；专用模板中的内容清单不作为固定章节配额。
- 原需求属于安全整改时，先概述实际整改领域和阶段，引用带日期的原问题数、已修/残留结论及延期决定；后续兼容Bug作为增量，不能替代完整整改范围。没有新复核不得把历史计数当作当前扫描结果。
- 先查已有真人确认及测试/发布记录。逐项写已上线、已验收、待验收、待确认或未纳入本次；注明验收环境和范围。已通过的微信登录不因后续邮箱缺回执被整体改成未验收。
- 技术实现、详细测试计数、主机路径、制品指纹和排障过程集中到内部技术文档。正文保留必要的业务限制，开放问题集中一次列出具体动作与责任角色。
- 项目固定时间线服务非开发读者，不为每次发布重复创建业务公告；需要通知时从对应条目提炼。实际发送仍需明确授权，不随文档更新自动发送或改变知识库权限。
- 产品版本来自仓库声明的唯一版本源，文档修订与记录编号分别表示。补登记现有正式版要区分原上线日期、基线登记日期、运行源码和登记提交，不重新部署或虚增一次发布。
